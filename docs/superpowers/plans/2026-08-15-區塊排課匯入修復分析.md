# 區塊排課工作檔匯入 — 問題分析與修復計畫

## 問題 1：科目名稱「國語文」非系統標準名稱

### 根因分析

**檔案**：`src/utils/blockScheduleExcelImport.js`（第 7-15 行）

```js
const SUBJECT_ALIASES = {
  國: '國語文',
  國語: '國語文',
  國1: '國語文',
  國2: '國語文',
  數: '數學',
  數1: '數學',
  數2: '數學',
}
```

流程：
1. Excel 儲存格寫 `504、509國1` → 解析出 rawSubject = `國1`
2. `SUBJECT_ALIASES['國1']` → `'國語文'`
3. `normalizeSubject('國語文')` → `'國語文'`（CANONICAL_MAP 無此鍵，原樣回傳）
4. 但系統標準科目名稱是 `語文-國語`（見 `schedule.js` standardDomainSettings）
5. 科目比對失敗 → 出現 UNKNOWN_SUBJECT 阻擋錯誤

**正確的系統科目名稱**（`schedule.js` standardDomainSettings）：
- `語文-國語`（非 `國語文`）
- `數學`（正確，無問題）

### 修復方案

修改 `SUBJECT_ALIASES` 將國語相關別名指向系統標準名稱 `語文-國語`：

```js
const SUBJECT_ALIASES = {
  國: '語文-國語',
  國語: '語文-國語',
  國1: '語文-國語',
  國2: '語文-國語',
  數: '數學',
  數1: '數學',
  數2: '數學',
}
```

**影響範圍**：
- `blockScheduleExcelImport.js`：SUBJECT_ALIASES 修改
- `tests/blockScheduleExcelImport.test.js`：所有期望 `targetSubject: '國語文'` 的斷言改為 `'語文-國語'`

## 問題 2：教師簡寫比對失效

### 根因分析

**檔案**：`src/utils/blockScheduleExcelImport.js`（第 94-108 行）

```js
function resolveTeacher(rawName, teachers, blockers, cell) {
  const candidates = teachers.filter((teacher) => teacher?.type === 'special_ed_resource')
  const exact = candidates.filter((teacher) => teacher.name === rawName)
  const matches = exact.length > 0 ? exact : candidates.filter((teacher) => teacher.name?.endsWith(rawName))

  if (matches.length === 0) {
    addIssue(blockers, 'MISSING_TEACHER', `找不到特教資源教師「${rawName}」`, cell)
    return null
  }
  if (matches.length > 1) {
    addIssue(blockers, 'AMBIGUOUS_TEACHER', `教師「${rawName}」有多個符合項目`, cell)
    return null
  }
  return matches[0]
}
```

問題場景：
- Excel 寫 `504、509國1 (文迪)` → rawName = `文迪`
- 資料庫教師：`謝文迪`（type: special_ed_resource）
- 精確比對：`謝文迪 === 文迪` → false
- 尾綴比對：`謝文迪.endsWith('文迪')` → **true** ✅

等等，`endsWith` 應該能匹配「文迪」到「謝文迪」。讓我再檢查…

實際上 `endsWith` 是能匹配的。問題可能出在：
1. 传入的 teachers 清單可能不是完整的資料庫教師清單
2. 或者 teacher.type 不是 `special_ed_resource`

需要確認 SpecialCourseView.vue 傳遞 teachers 的邏輯。

【更新】已確認 Prisma schema 教師 type 欄位定義：
```
type String // homeroom(導師), subject(專任), admin(行政)
```

**資料庫中沒有 `special_ed_resource` 這個 type！**

`resolveTeacher` 的 `teachers.filter(t => t?.type === 'special_ed_resource')` 永遠回傳空陣列，
因此所有教師比對都會直接走向 MISSING_TEACHER 錯誤。

### 修復方案（確定）

**移除 type 限制，改為全量比對**：

```js
function resolveTeacher(rawName, teachers, blockers, cell) {
  // 精確比對所有教師
  const exact = teachers.filter((t) => t?.name === rawName)
  if (exact.length === 1) return exact[0]
  if (exact.length > 1) {
    addIssue(blockers, 'AMBIGUOUS_TEACHER', `教師「${rawName}」有多個符合項目`, cell)
    return null
  }

  // 尾綴比對（如「文迪」匹配「謝文迪」）
  const suffixMatches = teachers.filter((t) => t?.name?.endsWith(rawName))
  if (suffixMatches.length === 1) return suffixMatches[0]
  if (suffixMatches.length > 1) {
    addIssue(blockers, 'AMBIGUOUS_TEACHER', `教師「${rawName}」有多個符合項目`, cell)
    return null
  }

  // 包含比對（如「謝」匹配「謝文迪」——僅在單字時使用）
  if (rawName.length === 1) {
    const includesMatches = teachers.filter((t) => t?.name?.includes(rawName))
    if (includesMatches.length === 1) return includesMatches[0]
    if (includesMatches.length > 1) {
      addIssue(blockers, 'AMBIGUOUS_TEACHER', `教師「${rawName}」有多個符合項目`, cell)
      return null
    }
  }

  addIssue(blockers, 'MISSING_TEACHER', `找不到教師「${rawName}」`, cell)
  return null
}
```

**比對優先級**：
1. 精確比對（全量教師）
2. 尾綴比對（全量教師）— 處理「文迪」→「謝文迪」
3. 包含比對（僅單字時）— 處理「謝」→「謝文迪」
4. 皆未匹配 → MISSING_TEACHER 阻擋
